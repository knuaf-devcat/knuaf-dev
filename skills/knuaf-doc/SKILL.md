# 창업논문 작성·검토

한 작업폴더에서 처음 응답할 때 다음 제작자 표시를 한 번 보여주고 도구 이름과 저장 위치를 알린다. 이어지는 세션에서 정본이 이미 있으면 다시 보여주지 않는다. 논문·엑셀 본문이나 학생 저자란에는 넣지 않는다.

> knuaf-doc · 창업논문 작성 도우미
> prod. 특용작물전공 24학번 김대욱

첫 사용에는 [문서 읽기 준비](references/parser-setup.md)에 따라 현재 사용 가능한 파싱 MCP·스킬·플러그인·CLI를 먼저 확인한다. 필요한 파일을 읽을 수 있는 기존 도구를 재사용하고, 없거나 필요한 기능이 부족할 때만 Kordoc을 자동 준비한다. 도구 선택·설치 명령을 학생에게 맡기지 않는다. 설치 준비는 작성 기준 선택과 별개이며 자료를 자동으로 현재 원고로 채택하지 않는다.

 학생에게 JSON, 명령어, 모델 등급을 배우도록 요구하지 않는다. 현재 구현은 로컬 검토용이다. 스킬이 Ⅰ~Ⅵ 작성·내용검토·본문/재무 수치대조·DOCX·XLSX를 마쳐도 한글 마무리와 교수 승인은 사용자 일이다. 전체 수용·독립 내용검토·다른 환경 시험이 끝나기 전 학교 최종 제출 완료라고 말하지 않는다. 자동 최종 승인은 지원하지 않는다.

## 시작·재개

첫 자료 질문 전에 [현재 작성물 선택](references/intake-selection.md)을 읽는다. 현재 원고·엑셀의 파일명/위치 또는 첨부를 먼저 받고(Q1a), 참고자료 폴더를 별도로 받는다(Q1b). 지정한 원고의 현재성·작목/주제·작성 목적을 짧게 확인한 뒤(Q1c) 그 기준으로 진행한다. 폴더 안의 초안·엑셀·project.json 존재만으로 현재 작성물을 선택하거나 이어쓰기를 시작하지 않는다. 이미 명확히 확인된 선택·없음 답변은 재사용한다.

- “시작하기”: 사용자가 지정한 폴더가 곧 작업폴더다. 그 안에 새 하위 폴더를 만들지 말고 지정한 폴더에 `scripts/gg.py init <폴더>`를 실행한다. `init`은 `project.json`과 자기 하위 폴더만 만들고 기존 파일에는 손대지 않으므로, 학생 자료가 이미 들어 있는 폴더에도 그대로 실행한다. 원본 학교 지침·학생 답변은 읽기 전용으로 보존한다. 정본이 이미 있으면 `init` 대신 “이어서 하기”로 간다.
- “이어서 하기”: `scripts/gg.py status <폴더>`와 `next <폴더>`를 실행하고 현재 정본 및 대상 절을 읽는다. 현재 작성 대상으로 확인한 폴더에 `project.json`이 없으면 원본을 그대로 둔 채 `import <기존폴더> --out <새폴더>`를 사용한다. import는 인터뷰·가정표·증거·절 원본의 바이트와 본문을 보존하고 수치·미결·중복·충돌을 `migration/inputs.json`에 기록한다. 가져온 뒤 `check <폴더>`가 내는 `migration-review` 항목(명령이 아니라 검사 ID다)을 따라 보존된 원답변부터 대조해 사실을 등록하며, 재인터뷰하거나 기존 검증을 자동 승격하지 않는다.
- “고칠 부분 보기”: `check <폴더>`의 위치별 결과와 내용검토 결과를 구분해 설명한다.
- “검토본 받기”: `export <폴더> --kind review`. 생성된 실제 경로와 미검증 항목을 알려준다. 교수 승인으로 표시하지 않는다.

명령은 이 스킬의 실제 `scripts/gg.py` 경로와 현재 Python 실행기를 사용한다. 최소 Python 3.10이 필요하며(3.9 이하는 `gg.py`가 안내 후 종료) `scripts/gg_deps.py python <폴더>`가 가리키는 인터프리터를 우선한다. 특정 홈 경로나 다른 호스트 설치를 가정하지 않는다. 먼저 `doctor <폴더>`로 설치 탐지 정보를 확인하되 탐지가 실제 기능 시험을 대신하지 않는다. `doctor`의 `lock.verdict`가 `stale_releasable`이면 `unlock <폴더>`로 잔류 잠금을 해제할 수 있고, `history <폴더>`·`restore <폴더> --revision N --expected-revision M`으로 이전 정본 스냅샷을 새 개정으로 되돌릴 수 있다(절 파일·build/는 건드리지 않음).

## 불변 조건

1. 기계 판정 정본은 `project.json` 하나다. 원답변·원문과 절 DRAFT는 파일로 보존하고 ID·위치·해시·개정으로 연결한다. 상태판·가정표·기존 검증 문자열은 승인 근거가 아니다.
2. 미제공·모름·명시적 없음·해당 없음·제공 거부를 합치지 않는다. 사실·관측·목표·가정·계산을 구분한다. 학교 지침이나 가격이 없으면 해당 판정만 보류하고 관련 없는 초안을 계속 저장한다.
3. 질문은 field ID와 결정 버전으로 식별한다. 질문 1회+도움 1회 후 해당 항목만 보류한다. 표현 변경으로 횟수를 초기화하지 않는다. 세부 규칙은 [mid-work-questions](references/mid-work-questions.md)가 소유한다.
4. 수치·규칙·본문 변경은 의존 검토와 출력을 무효화한다. 계산 오류는 사용자 선택으로 통과시키지 않는다. 적자는 정직하게 서술할 수 있다.
5. 기계검사, 내용검토, 실제 출력검토, 교수 승인은 별개다. 같은 작성자의 자가점검은 독립검토가 아니다. 독립검토가 없으면 보고서 첫 줄에 그 사실을 표시한다. `submission_candidate`는 스킬 검사 완료·교수 확인 전이며, 한글 글꼴·여백·페이지 번호·HWP 저장은 `user_finish_pending`으로 남긴다. 사용자 미완료는 Ⅰ~Ⅵ 작성과 DOCX/XLSX 작업을 막지 않는다. 자동 통과·N/A로 바꾸지 않는다.
6. 저수준 DOCX/XLSX는 검토 전이다. 제출 후보에는 현재 입력 및 출력 해시에 연결된 필수 검사와 증거가 필요하다. 도구 누락·실행 실패·손상·stale는 면제 사유가 아니다. HWP 제출이면 저장 후 재열기·렌더·표/인용/핵심 수치 대조가 필요하며, 그 확인은 사용자 소유로 표시한다.
7. 작업은 모델 이름이 아니라 **역할**로 나눈다. 메인은 인터뷰·판단·통합을 맡고, 자료 해석·출처 정리·학교 지침 대응·장별 초안·윤문은 자료 담당에게, 단순 추출은 로컬 도구에 맡긴다. 독립 내용검토는 그 글을 쓰지 않은 담당이 한다. 사용자가 명시한 작업별 모델·effort 지시가 최우선이며, 지정이 없으면 현재 호스트에서 쓸 수 있는 경로를 [model-routing](references/model-routing.md)에 따라 고른다. 첫 자료 열람·작성 전에 이 문서를 읽는다. 외부 모델·과금 경로를 자동 탐지 호출하거나 대체하지 않는다. 별도 담당을 둘 수 없는 호스트에서는 메인이 같은 품질 계약으로 수행하고 실효 모델을 기록한다. 채팅 전용이면 자동 저장·기계검사·재계산 완료를 주장하지 않고 복사 가능한 인계 묶음을 제공한다.

## 인터뷰에서 작문으로

문항 구성·되묻기·모름 처리·저장은 [interview-guide](references/interview-guide.md)가 소유하고, 질문 제시 형태는 [interview-ui](references/interview-ui.md)를 따른다. 핵심 프로필이 잡히면 선택 이유·농장명 의미·경영철학·포부를 작성자가 구성한다. 인터뷰에 없는 문장이라는 이유만으로 금지하지 않는다. 실제 과거 경험·계약·성과·수치의 창작과는 구분한다. 학생 본인의 1인칭으로 쓰되 본문에서 법적 성명을 화자처럼 반복하지 않고 `본인` 또는 주어 생략을 사용한다. 사용자가 확정한 작목·사업지·규모·시설·운영방식은 실제 사업계획으로 서술하며, 증빙 미확보를 이유로 이를 후보·검토 중·미결정 계획으로 되돌리지 않는다. 상세 기준은 [narrative-expansion](references/narrative-expansion.md)을 따른다. 내용 확장과 사실 대조를 마친 뒤 [한글 윤문 연결](references/korean-polishing.md)에 따라 `im-not-ai`의 `humanize-korean`을 적용한다.

작문 전에는 같은 지침의 도입 선택·문단 배치 기준을 사용자 자료와 장별 목적에 맞게 적용한다. 승인된 사례의 서사 순서나 소제목 유무를 공통 틀로 복제하지 않으며, 완성 후에는 [내용 품질 기준](references/exemplar-quality.md)으로 문단의 중심 내용·전환·반복을 사실 정확성과 별도로 점검한다. 비교·추세·공간·일정·재무 흐름처럼 글과 표만으로 핵심 판단이 잘 드러나지 않는 내용은 그래프·지도·도식이 이해를 실질적으로 높이는지 검토한다. 그림 수를 일률적으로 채우지 않으며, 필요한 시각자료에는 출처·축·단위·범례와 본문 해석을 붙이고 없는 데이터는 만들지 않는다. 최종 DOCX/PDF에서는 실제 렌더의 가독성과 본문 연결을 확인한다.

학교 졸업논문은 확정된 영농사업계획의 제출을 목표로 작성한다. 작성 중 필요한 사용자 프로필이나 중요한 계획 결정이 부족하면 [질문과 변경](references/mid-work-questions.md)에 따라 해당 항목을 추가 인터뷰한다. 확정한 계획은 실제 토지계약·대출 실행·판매 실적이 없다는 이유만으로 미정으로 되돌리지 않으며, 미응답이나 작성자의 제안을 사용자 결정으로 간주하지 않는다. 조사·산정한 계획값의 근거와 계산을 검토하며, 계획상 수익과 실제 발생한 성과는 구분한다.

사업지 지번은 인터뷰에서 확인하되, 사용자가 읍·면·리 수준으로 입지를 확정하고 상세 지번을 모르면 그 주소를 사용한다. 별도의 학교·교수 요구가 없는 한 지번 부재만으로 작성·검토 통과를 막지 않는다. 현장 특성과 가격 근거는 확인한 지역·필지 범위를 넘겨 단정하지 않는다.

- 산출물 생성 명령·플래그·보장 범위: [output-tooling](references/output-tooling.md)
- 실행 의존성·프로젝트 전용 환경: [package-install](references/package-install.md) — `gg_deps.py doctor`가 설치 판정의 정본이다.
- 학교 목차·규칙: 사용자가 제공한 학교 작성요령 원문에서 적용 규칙과 위치를 등록한다. 현재 확인된 **2020 공식 PDF**에서만 1–5쪽을 지침, 6쪽 이후를 양식·예시로 나눠 기록한다. 다른 판본은 해시·물리 페이지를 먼저 등록하고 분할을 다시 검토한다. 표지·표 양식은 원문을 가깝게 따른다. 본문을 현재 계획에 맞게 실질적으로 보완하면 [source-contract](references/source-contract.md)의 작업 기록에 이유를 남긴다. 재배포권 때문에 학교 규칙 추출본은 이 패키지에 없다. 사용자의 로컬 설치에 학교 목차·서식 추출본이 따로 있으면 보조 대조에만 쓰고, 원문 대신 근거로 삼지 않는다. 재배포권이 확인되지 않은 학교 규칙 추출본·글꼴은 패키지에 포함하지 않는다. 이 보조 파일이 없어도 원문 기반 자료 정리는 가능하며, 원문 없는 목차·서식 확정은 보류한다.

학교 원문이 최우선이다. 최신 학교/학과 공지와 이번 논문의 명시적 교수 지시를 확인하고 충돌은 위치와 함께 기록한다. 김원섭 선배논문(교수 강의자료)은 내러티브 품질 벤치마크로만 활용하고 공식 규칙을 덮어쓰지 않는다. 서민서 XLSX는 다른 작성자의 사용자 제공 재무 작성예시·템플릿이므로 제공되면 원본을 복제해 우선 사용한다. 선배 논문·엑셀 예시의 학생 정보·고정 가격·비율·연도·이익률은 가져오지 않는다. 이전 보조 문서의 모델 배치·상태 문자열·전역 중지 지시는 새 계약의 근거가 아니다.

재무 작성은 제공된 학교 양식의 입력·자동계산 역할을 먼저 확인한다. 어느 시트가 입력이고 어느 시트가 자동계산인지, 입력 셀에 무엇을 쓰고 기존 수식을 어떻게 보존하는지는 [excel-template](references/excel-template.md)의 「입력 시트 역할」을 따른다. 시트 번호·색을 기억에 의존해 단정하지 말고 실제 시트명·탭 색·원본 해시를 확인한다.

## 출력 지원 한계

DOCX·XLSX·Office 변환의 명령·플래그와 각 경로의 보장 범위는
[output-tooling](references/output-tooling.md)을 따른다. 산출물을 만들기 전에 읽는다.
생성·변환·기계검사 완료는 교수 승인이 아니며 제출 완료로 자동 승격되지 않는다.
DOCX 생성 후 한글에서 할 일(글꼴·여백·페이지 번호)은 사람이 확인하기 전까지
완료로 표시하지 않으며, 그 세 가지가 Ⅰ~Ⅵ 작성을 막지도 않는다.

원본·개인 자료는 외부로 보내거나 패키지에 포함하지 않는다. 공개 배포·교수 전달·파서 준비 외 추가 설치는 별도 승인 범위다. 사용자 결정에 따라 문서 읽기에 필요한 Kordoc의 전용 캐시 설치는 첫 사용 준비에 포함한다.
