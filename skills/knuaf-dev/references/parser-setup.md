# 첫 사용 문서 읽기 준비

사용자 결정 2026-09-07: 학생은 파서·MCP 개념이나 설치 명령을 배울 필요가 없다. 스킬이 기존 문서 읽기 도구를 확인하고, 필요한 경우에만 준비해 읽기를 실행한다. 필요한 도구의 자동 준비는 첫 사용에 포함하며, 학생에게 같은 설치 선택을 반복해서 묻지 않는다. 호스트·운영체제가 직접 요구하는 권한 화면은 우회하지 않는다.

## 자동 준비

**설치보다 기존 도구 확인이 먼저다.** 학생에게 도구 종류나 설치 여부를 묻지 않고 스킬이 다음 순서로 확인한다.

1. 현재 호스트에 노출된 도구와 사용 가능한 스킬·플러그인에서 문서 읽기 기능을 확인한다. 관련 스킬이 있으면 그 사용법을 읽는다. 연결된 로컬 Kordoc MCP나 다른 파서가 해당 파일 형식과 필요한 텍스트·표를 처리할 수 있는지 확인한다. 설치 목록에 이름만 있는 것, 비활성 플러그인, 호출할 수 없는 MCP는 실행 가능 증거가 아니다. 숨겨진 전체 홈 폴더나 다른 작업의 설정·인증정보를 광범위하게 검색하지 않는다.
2. 사용할 수 있는 기존 도구가 있으면 [intake-selection.md](intake-selection.md)에서 용도가 확인된 파일로 실제 읽기를 수행한다. 텍스트/표·원문 위치·필요한 이미지 등 해당 작업에 필요한 결과를 확인하고, 충분하면 그 도구를 계속 쓰며 `gg_kordoc.py ensure`나 별도 설치를 실행하지 않는다. 자료를 아직 받지 않았다면 연결/지원 형식만 확인해 ‘읽기 검증 대기’로 두고 설치를 서두르지 않는다.
3. 연결된 도구가 없거나 필요한 형식을 처리하지 못할 때 CLI를 확인한다. `scripts/gg_kordoc.py ensure`는 PATH의 기존 Kordoc을 우선 검사한다. 호스트에서 확인한 다른 설치 위치가 있으면 `--kordoc <실제 실행파일>`을 전달한다. 버전 이름만으로 교체하지 않으며 필요한 CLI 옵션과 실행을 확인해 호환되는 설치를 재사용한다. 전용 캐시나 pnpm 설치는 기존 CLI를 사용할 수 없을 때만 준비한다.
4. 기존 경로와 스킬 전용 캐시 모두 사용할 수 없을 때만 Kordoc 4.13.1을 전용 캐시에 설치한다. 기존 도구를 삭제·업데이트·재등록하지 않는다. 전역 패키지·다른 프로젝트 의존성·Codex MCP 설정은 변경하지 않는다. 이때만 “문서를 읽는 데 필요한 도구를 준비할게요. 처음 한 번은 시간이 조금 걸릴 수 있어요.”라고 안내한다.

재사용 여부는 형식·작업별로 판단한다. PDF를 읽었다고 HWP나 병합 표까지 지원한다고 추정하지 않는다. 이미지 OCR이나 온라인 업로드가 필요한 도구는 기존 설치가 있다는 이유만으로 추가 다운로드·외부 전송 승인을 얻은 것으로 간주하지 않는다. 원문 손상·잘못된 경로·권한 오류를 기능 부족으로 오인해 같은 파서를 중복 설치하지 않는다. 실패 이유가 불명확하면 관련 읽기만 보류하고 가능한 작업을 계속한다.

선택한 도구의 실제 호출 경로, 지원/미검증 형식, 입력 해시와 결과 위치, 재사용 또는 신규 설치 사유를 작업폴더의 감사 기록에 남긴다. 기록은 현재 실행 증거에 연결하고, 이름만 적거나 오래된 성공 기록만으로 준비 완료라고 말하지 않는다.

기존 도구가 바로 실행되면 Node.js·pnpm 탐지나 설치를 추가로 요구하지 않는다. 기존 CLI 실행에 Node.js만 부족하거나, 새 전용 캐시 설치에 필요한 Node.js·pnpm이 없을 때에만 호스트의 번들 실행환경 조회 도구를 사용한다. Codex Desktop에서는 `load_workspace_dependencies`가 제공되면 조회하여 반환된 Python·Node·pnpm의 실제 경로를 사용하고 `--node`, `--pnpm`으로 전달한다. 고정된 개발자 홈 경로를 복제하지 않는다. 다른 환경에서는 실제 제공된 런타임을 확인한다. 사용 가능한 실행환경을 찾지 못하거나 네트워크·권한에 막히면 실패 이유와 필요한 조치를 짧게 알리고, 인터뷰와 이미 읽을 수 있는 자료 작업은 계속한다. 설치되지 않았는데 준비 완료라고 말하지 않는다.

설치 성공은 문서 파싱 성공이 아니다. 실제 확인된 자료를 처음 받을 때 아래 읽기 검증을 수행한다. 자료가 아직 없으면 읽기 검증은 미실행으로 남기며 임의로 폴더의 옛 원고를 고르지 않는다.

## 자료 읽기

[intake-selection.md](intake-selection.md)에서 용도가 확인된 파일에 대해서만 선택한 기존 도구로 읽는다. Kordoc CLI를 선택한 경우에는 `scripts/gg_kordoc.py parse <파일> --out <새.md>`를 실행하고, 필요하면 확인한 경로를 `--kordoc`으로 전달한다. 현재 원고 후보의 확인용 읽기와 참고자료 발췌를 구분한다. 실행 결과의 실제 출력 경로·입력 해시·제한사항을 출처 기록에 연결한다. 단순 텍스트 생성만으로 표·각주·수치·물리 페이지·글자 위치 보존을 보장하지 않는다. 표 구조와 핵심 수치를 실제 원문과 대조한다.

문서는 로컬에서 처리한다. 이 helper는 원문 업로드, 클라우드 OCR, 모델 공급자 호출을 하지 않으며 파싱 시 `KORDOC_OFFLINE=1`을 사용한다. 스캔 문서·미지원 파일·손상 파일은 자동 성공으로 표시하지 않는다. 추가 OCR 모델 설치 등은 현재 지원 범위와 권한을 확인한 뒤 별도로 처리한다.

## MCP와의 관계

기존에 사용할 수 있는 로컬 파싱 MCP·스킬·플러그인을 먼저 재사용한다. Kordoc은 CLI와 MCP를 제공하며 새로 준비해야 할 때의 기본 경로는 로컬 CLI다. MCP 재등록·대화형 setup·앱 재시작을 첫 인터뷰의 필수 조건으로 만들지 않는다. 이미 연결된 Kordoc MCP도 실제 동작을 확인하면 사용할 수 있지만, 설치 표시만으로 문서를 읽었다고 주장하지 않는다.

확인한 공식 출처: [Kordoc 저장소](https://github.com/chrisryugj/kordoc), [CLI와 MCP 사용법](https://github.com/chrisryugj/kordoc/blob/main/README.md). 새로 설치하는 버전은 자동 최신화하지 않으며 업데이트는 별도 검증 후 바꾼다. 기존 설치는 필요한 기능을 확인해 재사용한다.

산출물 생성(XLSX·DOCX·PDF 검증)에 필요한 Python 패키지 의존성은 이 문서의 파서 준비와 별개이며 [package-install.md](package-install.md)의 선언·프로젝트 전용 환경 계약을 따른다.
