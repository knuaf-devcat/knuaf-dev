# 지침별 적용과 검토

상태는 `project.json`에 저장한다. 원문에서 분해한 지침 목록은 출처에 묶인 입력 파일이며, 별도 완료 원장이 아니다. 절 Markdown의 `STATUS`나 “규칙을 읽었다”는 선언만으로 준수 판정을 하지 않는다.

## 원문에서 등록하기

1. 학교 원본의 해시·개정·물리 페이지를 `sources`에 등록한다. 현재 확인한 2020 판의 1–5쪽은 작성요령, 6–26쪽은 양식·예시다. 다른 판본은 이 구분을 다시 확인한다.
2. 조항과 양식을 안정적인 ID로 분해해 `sources/guidelines/inventory.json`에 둔다. 각 항목에 원문 페이지·위치, 요구 요약, 적용 대상, 검증 방법, 조건을 기록한다. 원문 명시 지침(`instruction`), 양식(`form`), 예시(`example`)를 구분한다. 예시의 숫자·이름·날짜·분량을 의무로 승격하지 않는다.
3. `rules.guideline_profile`에 전체 ID 집합, 목록 파일 경로·해시, 원문 참조를 등록한다. 항목별 적용 상태와 본문·표 위치는 같은 ID의 `rules` 레코드에 연결한다. 작성할 때는 해당 항목과 원문 위치만 읽고, 전체 규칙을 매번 프롬프트에 복제하지 않는다.
4. 다른 검토자가 원문 전체와 목록을 대조해 누락·조건 오해를 확인한다. 파일 해시는 파일이 바뀌지 않았음을 증명할 뿐, 목록의 완전성을 증명하지 않는다.

## 항목의 판정

| 종류 | 확인할 것 | 완료 근거 |
|---|---|---|
| `machine` | 구조·숫자·연결 등 재현 가능한 검사 | 실제 검사 결과와 현재 입력에 묶인 검토 |
| `content` | 필수 내용·근거·해석·농장 선택의 타당성 | 작성자와 다른 검토자의 원문·본문 대조 |
| `visual` | 표지·표·목차의 위치·크기·간격·색상·쪽 나눔 | 실제 출력 파일과 전체 관련 페이지의 시각 검토 |
| `user_finish` | 한글 최종 글꼴·여백·쪽번호·HWP 마무리 | 사용자가 수행·확인하기 전까지 미완료로 표시 |

본문 인용 위치가 있다는 것과 지침을 충족했다는 것은 다르다. 내용·시각 검토에는 `coverage.guidelines`로 실제 확인한 ID를 연결하고, 현재 입력 fingerprint와 보고서 해시를 등록한다. 시각 검토는 검토한 출력 파일 해시도 연결한다. 수치나 원문·본문·출력이 바뀌면 영향을 받은 검토를 다시 수행한다.

조건부 항목은 확인된 사실로 조건이 거짓임을 입증한 경우에만 해당 없음으로 처리한다. 모름·자료 부재·도구 실패를 해당 없음으로 바꾸지 않는다. 사용자 마무리는 자동 통과하지 않지만 스킬 개발·초안 작성을 중지시키지도 않는다.

## 완료 범위

- 개발 검증: 전체 지침이 분해·연결됐고, 정상 사례와 누락·변경·미검토 사례에서 검사가 올바르게 동작했는지 확인한다. 표시된 가상 자료로 시험할 수 있다.
- 개별 논문 검증: 그 학생의 실제 원고·재무·출력에 지침이 적용됐는지 별도로 확인한다. 개발 시험 통과를 학생 논문 통과로 복사하지 않는다.
- 최종 제출: 사용자 한글 마무리와 교수 승인 상태를 별도로 유지한다.

원문 없는 일반 프로젝트의 미설정 상태를 지침 통과라고 표시하지 않는다. 학교 원문을 등록한 프로젝트에 전체 목록이 없으면 학교 지침 판정을 보류한다. 보류 중에도 인터뷰·조사·초안·검토본 저장은 계속할 수 있다.

## 원문 안의 상충

현재 2020 자료에서는 4쪽의 머리지면 목록과 6–9쪽의 실제 양식 순서, 1쪽의 중간제목 크기와 5쪽의 하위 번호 크기가 서로 다르다. 3쪽의 캡션 지침과 뒤쪽 한글 표·그림 예시도 구분해 대조한다. 충돌을 숨기거나 양쪽 모두 준수했다고 기록하지 않는다. 출력 프로필에 채택한 기준과 이유를 남기고, 교수의 다른 지시가 들어오면 해당 항목과 산출물을 갱신한다.

이번 예시 양식 배치 개선은 원문 6–9쪽의 실제 양식을 구현하는 개발 선택이다. 이것을 학교 4쪽 목록의 폐기나 교수 승인으로 해석하지 않는다. 예시의 파란 글씨·[양식 N] 표시는 입력 안내이므로 완성 원고의 이름·제목·연월은 검정으로 출력하고, 미확인 값은 표시를 남긴다.

## 레코드 책임과 형식

학생은 사실·자료·계획과 미결 답변을 제공한다. 아래 파일·ID·해시·검토 메타데이터는 스킬이 작성하고 검사한다. 학생에게 JSON 작성이나 모델 선택을 요구하지 않는다.

- 작업폴더의 현재 출처는 `project.json.sources`에서 읽는다. 이것이 유일한 출처 정본이며, 개발 과정에서 쓰인 별도 인덱스 파일은 학생 프로젝트의 근거가 아니다.
- 목록 파일의 권장 위치는 `sources/guidelines/inventory.json`이다. 실제 읽기 경로는 `rules.guideline_profile.inventory.path` 한 곳에서 정하고 `sha256`을 비교한다.
- 목록은 `schema: "gg-guideline-inventory/v1"`, `source: {id, sha256, physical_page_count}`, `requirements`, `conflicts`를 가진다. 항목의 필드는 `id`, `page`, `locator`, `requirement`, `applies_to`, `kind`, `authority`, `condition`, `verification`, `source_role`, `certainty`이며 `gg_guidelines.py`는 모든 항목에서 마지막 두 필드도 요구한다. `applies_to`는 적용 대상 설명이며 학생 프로젝트의 절 ID로 단정하지 않는다.
- 2020 원문 목록은 페이지 역할 `source_role: instructions|forms_examples`와 근거 성격 `certainty: explicit|explicit_annotation|template|inferred`도 보존한다. 뒤쪽의 명시적 작성 안내와 단순 예시를 구분한다.
- 프로필은 `id: "guideline_profile"`, `profile_id`, `source_refs: [{id, revision, locator}]`, `inventory: {path, sha256}`, `requirement_ids`를 가진다. 현재 적용 여부·본문 위치·조건부 면제는 목록 파일을 수정하지 않고 같은 ID의 `project.json.rules`에 등록한다.
- 원문 충돌은 목록의 `conflicts`에서 찾고, 채택한 기준은 프로필의 `conflict_resolutions`에 ID·근거·이유·영향 항목으로 연결한다. 해결되지 않은 충돌을 양쪽 동시 준수로 처리하지 않는다. 선택한 기준에 따른 구현과 교수 승인은 별개다.

DOCX의 `font` 검사는 파일 안에 선언·적용된 글꼴을 확인한다. 설치된 실제 글꼴 및 한글 최종 출력 확인과 다르다. 신명조가 없는 환경에서 대체 글꼴로 렌더했다면 그 사실을 출력 검토에 적고, 사용자 최종 확인 상태를 유지한다.

기계 항목의 검토는 `docx`, `xlsx`, `calculation` 종류를 사용하며 `coverage.machine_checks`에 항목 ID, 검사 ID, 통과 여부, 검사 보고서 경로·해시, 대상과 현재 fingerprint를 연결한다. 단순 내용검토를 기계 검사로 대체하지 않는다. 시각 검토는 `render`를 사용하고 `coverage.output_id`·`coverage.output_file_hash`를 실제 출력과 연결한다.

해당 없음은 inventory에 실제 조건(`condition`)이 정의된 항목에서만 허용한다. 현재 규칙에 이유, 조건을 거짓으로 평가한 사실 ID·개정, 증거, 독립 검토를 연결한다. 원문이 무조건 요구하는 항목에 임의의 조건을 만들어 면제하지 않는다. 새 교수 지시로 적용 조건이 바뀌면 그 지시를 새 출처로 등록하고 목록·프로필을 검토하여 개정한다.

## 작성 방식과 필수 항목을 구분하기

번호·인용·단위의 표기 규칙은 해당 표현을 사용할 때 적용한다. 번호 체계가 아홉 단계라고 해서 실제 논문에 아홉 단계 제목을 모두 만들거나, 두 저자 인용 예시를 맞추려고 존재하지 않는 문헌을 추가하지 않는다. 검토자는 사용된 표현 전체에서 위반 여부와 미사용 범위를 함께 기록한다. 필수 내용 항목은 제목·“확인 필요” 문구만으로 충족하지 않으며, 자료의 범위 안에서 설명·계산·선택 이유를 작성한다. 지침 설명 자체를 논문 본문에 삽입해 준수 근거로 삼지 않는다.

개발용 합성 사례에서는 가상의 입력과 실제 문헌의 연구 결과를 분리한다. 지역·농장 값은 합성 원자료에 기록하고, 인용 연구의 결과는 연구 대상·조건·한계를 유지한다. 합성 입력으로 완료한 시험의 증거를 실제 학생 프로젝트에 재사용하지 않는다.

## DOCX 서식 검사 실행

`python3 scripts/gg_school_format.py <검토본.docx> --out <새-검사결과.json>`으로 A4, 본문 크기·줄간격·첫 줄 들여쓰기·양쪽 정렬을 측정한다. 이 검사는 스킬이 삽입하는 `gg_body_1` 책갈피가 있는 DOCX를 대상으로 한다. 책갈피나 본문이 없으면 검사를 보류한다. 제목·본문 글꼴 선언도 측정하지만 실제 글꼴 설치·페이지 시각 검토·한글 최종 확인을 대체하지 않는다. 결과 JSON은 현재 출력 해시와 함께 검토에 등록한다.

## 무엇을 근거로 삼는가 (SKILL.md 에서 옮김)

학교 목차·규칙은 사용자가 제공한 **학교 작성요령 원문**에서 적용 규칙과 위치를
등록한다. 현재 확인된 **2020 공식 PDF** 에서만 1–5쪽을 지침, 6쪽 이후를 양식·예시로
나눠 기록한다. 다른 판본은 해시·물리 페이지를 먼저 등록하고 분할을 다시 검토한다.
표지·표 양식은 원문을 가깝게 따른다. 본문을 현재 계획에 맞게 실질적으로 보완하면
[source-contract](source-contract.md) 의 작업 기록에 이유를 남긴다.

재배포권 때문에 학교 규칙 추출본은 이 패키지에 없다. 사용자의 로컬 설치에 학교
목차·서식 추출본이 따로 있으면 **보조 대조에만** 쓰고 원문 대신 근거로 삼지 않는다.
재배포권이 확인되지 않은 학교 규칙 추출본·글꼴은 패키지에 포함하지 않는다. 이 보조
파일이 없어도 원문 기반 자료 정리는 가능하며, 원문 없는 목차·서식 확정은 보류한다.

**학교 원문이 최우선이다.** 최신 학교/학과 공지와 이번 논문의 명시적 교수 지시를
확인하고 충돌은 위치와 함께 기록한다.

- 김원섭 선배논문(교수 강의자료): 내러티브 **품질 벤치마크로만** 쓰고 공식 규칙을
  덮어쓰지 않는다.
- 서민서 XLSX: 다른 작성자의 사용자 제공 재무 작성예시·템플릿이므로, 제공되면 원본을
  복제해 우선 사용한다.
- 선배 논문·엑셀 예시의 **학생 정보·고정 가격·비율·연도·이익률은 가져오지 않는다.**
- 이전 보조 문서의 모델 배치·상태 문자열·전역 중지 지시는 새 계약의 근거가 아니다.
