# 자료 투입과 조사 투명성

공통 출처 ID·해시·물리 페이지·절/표 작업 기록은 [source-contract.md](source-contract.md)가 정본이다. 이 문서는 자료를 언제 읽고 어떤 발췌·조사 기록을 남길지에 집중한다.

## 1. 자료 투입 시점

자료 등록 전 [intake-selection.md](intake-selection.md)의 Q1a/Q1b/Q1c를 따른다. 현재 작성물 지정과 참고자료 폴더 제공을 구분한다. 아래의 직접 열람은 지정된 후보의 확인 또는 확인된 자료 처리이며, 폴더에서 찾은 초안을 현재 원고로 자동 채택하는 지시가 아니다.


파일 성격에 따라 필요한 시점이 다르다. 전부 초기에 받으면 쓰지도 않을 자료로
컨텍스트를 낭비하고, 전부 나중에 받으면 이미 쓴 원고를 뒤집는다.

| 구분 | 시점 | 방식 |
|---|---|---|
| 작성 중이던 본문·재무 엑셀 | 초기 필수 | 경로 확인 후 직접 열어 검증 |
| 학교 작성요령·선배 논문 | 초기 필수 | 경로 확인 (목차·문체 추출원) |
| 농업 자료·매뉴얼·시세 | 폴더 등록 | 인덱스만 만들고 필요할 때 선택 열람 |
| 웹 링크 | 수시 | 즉시 스냅샷 저장 후 인덱스 등록 |
| 교수 피드백·추가 자료 | 수시 | 즉시 등록 + 영향 절 판정 |

### 초기 필수인 이유
- 기존 원고의 현재성 확인과 이어쓰기 선택은 [intake-selection.md](intake-selection.md)를 따른다. 원고가 없으면 그 답을 보존하고 신규 작성으로 진행한다.
- 작성요령을 모르면 목차 뼈대를 세울 수 없다. 나중에 알면 전 장을 재편해야 한다.

### 폴더 등록 방식
참고자료는 파일별 첨부를 요구하지 않고 폴더 경로를 받는다. 현재 원고·재무 파일은 별도로 파일명/위치 또는 첨부를 받아 선택을 확인한다.

1. 폴더를 스캔해 03_sources.md 인덱스를 만든다(파일명·형식·크기·추정 주제). 각 항목에 `project.json.sources[*].id`, SHA-256(`hash`), 물리 페이지 또는 시트 범위, 현재 revision을 함께 적는다.
2. 각 절 작업에 들어갈 때 인덱스에서 관련 자료만 골라 읽는다.
3. **읽었으면 반드시 발췌본을 남긴다** (아래 1-1항). 읽고 넘어가지 않는다.
4. 인덱스에 있으나 어느 절에도 쓰이지 않은 자료는 lint WARN으로 보고한다.

## 1-1. 읽은 자료는 반드시 발췌본으로 남긴다

원본을 한 번 읽고 지나가면 그 내용은 **대화 컨텍스트에만 존재한다.**
세션이 압축되거나 다른 모델로 넘어가면 사라지고, 원본을 다시 파싱해야 한다.
HWP·PDF 파싱은 비용이 크고 표가 깨지므로 같은 결과가 나온다는 보장도 없다.

**원칙: 원본을 연 순간, 그 자리에서 발췌본을 만든다.**

### 저장 위치

    <작업폴더>/sources/
      web/          웹 링크 스냅샷 (2항)
      extracts/     사용자 첨부 파일 발췌본  ★
        <원본파일명>.md

### 발췌본에 넣을 것

    ---
    원본: <original-path>/선배논문_김OO.hwp
    형식: hwp | 추출: (사용한 파싱 수단) | 추출일: 2026-09-03
    등급: 2 | 역할: 문체·분량 참조 (규칙 근거 아님)
    추출범위: 전문 | 한계: 표 셀 일부 축약됨
    ---

    ## 구조
    (목차·시트 구성·장별 분량 등 뼈대)

    ## 이 논문에 쓸 것
    (해당 절과 연결지어 정리. 인용할 수치는 원문 표현 그대로)

    ## 원문 인용
    (그대로 보존해야 할 문장·수치·표. 요약하지 말 것)

### 요약만 남기지 않는다

요약은 이미 판단이 섞인 결과다. 나중에 다른 절에서 필요한 정보가
요약 단계에서 버려졌을 수 있다.
**수치·표·규정 문구는 원문 그대로 옮긴다.** 판단은 별도 항목에 적는다.

### 중복 파싱 방지와 시각 검증 예외

`sources/extracts/`에 같은 revision·범위의 발췌본이 있으면 텍스트 파싱을 반복하지 않는다. 다음 경우에는 원본을 다시 열 수 있다.

- 원본의 표·병합·각주·쪽 배치를 시각적으로 검증해야 할 때
- 원본 SHA-256, 물리 페이지, 추출 방법이 바뀌었을 때
- 기존 발췌본의 범위·한계로 해당 주장을 판정할 수 없을 때

재검토는 새 revision과 범위를 `source-contract.md` 계약 및 작업 기록에 남긴다. 기존 발췌본을 덮어쓰지 말고 보완 발췌본으로 추가한다.

### 중간 투입 처리
작업 도중 자료를 받으면 즉시 (1) 인덱스 등록 (2) 어느 절에 영향을 주는지 판정
(3) 이미 작성된 절에 영향을 주면 사용자에게 재검토 필요를 보고
(4) 재무 입력을 바꾸면 workflow-order.md의 재검산 게이트를 다시 돈다.

### 본문 설명에 쓸 도표와 데이터

절의 논점을 설명하는 원문 도표나 통계가 있으면 텍스트 요약만 남기지 않고 실제 페이지·표/그림 번호, 해석에 필요한 축·단위·범례·주석, 적용 가능한 범위와 이용 조건을 발췌 기록에 연결한다. 원문 도표 재사용과 원자료 재도식화의 선택·제작·본문 삽입은 [narrative-expansion.md](narrative-expansion.md)의 단계 E를 따른다. 자료 검색·목록 작성만으로 필요한 시각자료의 완성을 대신하지 않는다.

## 2. 웹 링크 처리

링크는 파일과 달리 내용이 바뀌거나 사라진다. 받는 즉시 고정한다.

1. 스냅샷 저장: 본문을 추출해 sources/web/ 아래 날짜_슬러그.md 로 저장한다.
2. 출처 등급 판정(3항)
3. 증거 원장 등록: locator에 URL, method에 취득 경로를 적는다.

스냅샷 머리말 항목: url / accessed(접속시각) / title / grade / method
링크가 죽어도 스냅샷이 근거로 남는다.

## 3. 출처 등급

| 등급 | 유형 |
|---|---|
| 1 | 정부·공공기관 공식 통계, 법령, 학술논문(DOI 확인) |
| 2 | 학회지·연구기관 보고서, 지자체 공고, 공공 DB |
| 3 | 언론 보도, 기관 보도자료, 업계 협회 자료 |
| 4 | 블로그, 커뮤니티, 쇼핑몰 상품페이지, 개인 SNS |

### 등급은 출처의 격이지 사실의 격이 아니다

같은 자료라도 **무엇을 주장하는 데 쓰느냐**에 따라 유효성이 다르다.
쇼핑몰 페이지는 4등급이지만, 거기 적힌 판매가는 **소매가에 대한 1차 증거**다.
문제는 그것을 '농가 수취가'로 바꿔치기할 때 생긴다.

그래서 차단 기준을 출처 등급만으로 정하지 않는다. **주장과 증거가 맞물리는지**를 본다.

### 하위 등급을 쓸 수 있는 경우

4등급이어도 아래 중 하나에 해당하면 본문에 쓸 수 있다.

**가) 그 자료가 주장 대상 자체일 때 (직접 관찰)**

쇼핑몰 소매가, 판매 페이지의 포장 단위, 업체 홈페이지의 설비 사양처럼
**그 사이트에 존재한다는 사실 자체가 근거**인 경우.

    쓸 수 있다: "온라인 소매가는 100 g당 6,000원 수준이다(A쇼핑몰, 2026-09-02 확인)"
    쓸 수 없다: "농가 수취가는 kg당 60,000원이다"  ← 유통단계가 다르다

주장 문장에 **출처 성격을 그대로 드러내야** 한다. '소매가'를 '단가'로 뭉개지 않는다.

**나) 상위 등급을 보강할 때 (보조 증거)**

1~3등급이 이미 그 주장을 뒷받침하고, 하위 자료가 **사례·현황을 덧붙이는** 경우.

    주장: 새싹 채소는 유통기한이 짧아 근거리 판매가 유리하다
    주 근거: [1등급] 농진청 저장성 연구
    보조:   [4등급] 지역 직거래 농가 블로그 - 실제 3일 내 판매 사례

보조 증거만으로 주장을 세우지 않는다. **상위 근거가 먼저 있어야 한다.**

**다) 복수 교차로 경향이 확인될 때**

같은 등급 자료 **3건 이상**이 독립적으로 같은 값을 가리키면 경향으로 쓸 수 있다.

    쓸 수 있다: "온라인 소매가는 kg당 6~8만원에 형성되어 있다(쇼핑몰 4곳, 2026-09-02)"

단일 출처는 안 된다. 확인 시점과 출처 수를 반드시 함께 적는다.

### 그래도 안 되는 것

아래는 하위 등급으로 대체할 수 없다. 상위 등급이 없으면 그 주장을 쓰지 않는다.

| 대상 | 필요 등급 | 이유 |
|---|---|---|
| 재무 입력값(단가·수량·시설비) | 2등급 이상 | 계산 전체가 여기서 파생된다 |
| 법령·제도·지원자격 | 1등급(원문) | 조항이 바뀌면 계획이 무효가 된다 |
| 학술적 사실(생육조건·성분) | 1등급(DOI) | 논문 인용은 실재 검증이 필수다 |
| 통계 수치(생산량·소비량) | 1~2등급 | 기관·연도가 특정되어야 한다 |

**재무 입력값 예외 하나**: 2등급 이상 자료가 존재하지 않는 신규 품목은
복수 교차(다항)로 얻은 값을 **시범값**으로 쓸 수 있다.
이때 `01_assumptions.md`에 `시범값·계약 후 교체` 라벨을 달고,
본문은 단정하지 않고 계산식이나 범위로 서술한다.

### 판정 절차

자료를 쓰기 전에 순서대로 확인한다.

    1. 이 자료가 주장 대상 자체인가        → 예: 사용 가능 (가)
    2. 상위 등급 근거가 이미 있는가         → 예: 보조로 사용 가능 (나)
    3. 같은 등급 3건 이상이 일치하는가      → 예: 경향으로 사용 가능 (다)
    4. 위 표의 '안 되는 것'에 해당하는가    → 예: 사용 불가
    5. 어디에도 없으면                    → 사용 불가. 상위 출처를 더 찾는다

### 기록 방법

하위 등급을 쓸 때는 증거 원장에 **어느 경우로 허용했는지** 남긴다.

    {"id":"R-041","kind":"price","claim":"온라인 소매가 100g당 6,000원",
     "source":"A쇼핑몰 외 3곳","grade":4,"allow":"direct-observation",
     "verified":"multi-source","note":"소매가 한정. 농가 수취가 아님"}

`allow` 값: `direct-observation`(가) / `supporting`(나) / `multi-source`(다)

**사유만 적으면 통과하지 않는다.** 하위 모델이 조사 결과를 들고 올 때
근거 없이 사유 토큰만 붙이는 것을 막기 위해 아래를 함께 요구한다.

| allow | 함께 적을 것 | 없으면 |
|---|---|---|
| `supporting` | `supports`: 상위 근거의 `R-nnn` | BLOCK |
| `multi-source` | `source_count`: 확인한 출처 수(3 이상) | BLOCK |
| `direct-observation` | claim·note에 유통단계 명시(소매가 등) | 재무 입력값이면 BLOCK |

    {"id":"R-042","kind":"stat","grade":4,"allow":"supporting",
     "supports":"R-014","source":"농가 블로그",...}

    {"id":"R-043","kind":"price","grade":4,"allow":"multi-source",
     "source_count":4,"source":"A몰, B몰, C몰, D몰","note":"시범값",...}

근거 없이 4등급을 쓰면 lint가 차단한다.

## 4. 조사 로그 (04_research_log.md)

사용자가 '어디까지 찾아봤는지, 이상한 자료를 가져온 건 아닌지' 확인할 수 있어야 한다.
결과만 적지 말고 과정을 적는다.

### 필수 기록 항목
1. 질문 요지 — 무엇을 물었나
2. 경로 — 자체검색 / 웹조사 / 브라우저 / 문서파싱 / 하위모델 위임 / 사용자제공
3. 확인한 출처 전체 — 채택한 것과 버린 것을 모두 적는다
4. 채택 결론과 근거
5. 배제 사유 — 왜 버렸는지
6. 한계 — 이 조사로 확인되지 않은 것

### 왜 배제 사유가 중요한가
채택한 것만 보여주면 유리한 것만 골랐는지 알 수 없다.
버린 것과 이유를 함께 남겨야 조사가 검증 가능해진다.

### 기록 서식
각 조사에 Q-nnn 번호를 붙이고 아래 순서로 적는다.
제목줄, 일시, 경로, 질문요지, 확인한 출처 표(출처·등급·내용·채택여부),
채택 결론, 배제 사유, 한계.
출처 표의 채택 열에는 O(채택) / X(배제) / 보류를 적는다.

## 5. 하위 모델 조사 결과 취급

위임 조사는 효율적이지만 결과를 그대로 신뢰하지 않는다.
실제 발생한 오류 유형(2026-09-02):

| 유형 | 사례 | 방어 |
|---|---|---|
| 소매가와 농가가 혼동 | 쇼핑몰 소매가를 농가 수취가로 제시 | 유통단계를 명시적으로 질문 |
| 비용 누락 | 표고 계산에서 인건비·수선비 0원 처리 | 직접 재검산 |
| 이중계산 | 재식밀도와 회전수를 곱해 실현 불가 물량 | 실측 사례로 역산 대조 |
| 자기모순 | 한 답변에 6배 차이 수치 공존 | 답변 내 일관성 검사 |

### 위임 프롬프트에 반드시 넣을 것

가격 조사에는 [price-research-routes.md](price-research-routes.md)의 품목·상품·거래 단계별 경로와 작업 계약을 함께 전달한다. 출처 목록은 조사 출발점이며 가격 증거가 아니다. 조회 결과·조회 조건·기준일을 실제 확인한 뒤 등록한다. 접근 오류, 품목 미등재, 선택 기간 거래 결과 없음, 조건 불일치, 공개 단가 미확인을 구분한다. 동일 검색을 반복하지 말고 조사한 범위와 다음 적합 경로를 기록한다. 부족한 가격은 해당 계산만 보류하며 무관한 논문 작성을 멈추지 않는다.

- 과거 발생한 오류 유형 명시('이런 실수가 있었으니 피하라')
- '제시한 수치가 현실적인지 스스로 검산하라'
- '확인 못 하면 확인 불가라고 하라. 지어내지 마라'
- 출처를 기관·자료명·연도·URL까지 요구

### 받은 뒤
- 수치는 직접 재계산해 대조
- 논문·법령은 별도 호출로 실재 검증
- 원장 verified는 검증을 실제 수행한 뒤에만 승격
