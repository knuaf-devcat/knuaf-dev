# 출력 생성 도구와 지원 한계

DOCX·XLSX·Office 렌더 경로의 명령과 플래그, 그리고 각 경로가 무엇을 보장하지
않는지를 정한다. 절 작성이 끝나 산출물을 만들 때 읽는다. 생성 성공은 교수 승인도
학교 제출 완료도 아니다.

`build_docx.py`는 제목·문단·pipe 표·로컬 그림·강조를 변환한다. 새 학교 원고 CLI는 `school_profile`의 `forms_1_to_4` 배치를 기본으로 사용한다. 표지·제출면·인준서는 각각 한 쪽, 목차는 실제 본문 북마크의 쪽번호를 참조한다. 프로필의 제목·학생·학과·지도교수·제출일·졸업일은 기존 답변에서 스킬이 구성하고, 제출일과 졸업일을 임의로 복제하지 않는다. 제목이 양식 영역을 넘으면 잘라내지 않고 보완을 알린다. 기존 Markdown과 저수준 라이브러리의 옛 배치는 호환을 위해 보존한다. 글꼴 가용성·모든 페이지 렌더·HWP 변환은 생성과 별도로 검증한다. DOCX 생성 후 한글에서 할 일은 (1) 글꼴 신명조 확인·변경 (2) 여백 위20/아래15/머리15/꼬리15/좌30/우30/제본0 mm (3) 페이지 번호다. 이 세 가지는 스킬 작성 완료를 막지 않으며, 사람이 확인하기 전까지 완료로 표시하지 않는다.

`scripts/gg_excel_template.py inspect|clear`가 제공된 제출 템플릿의 시트·입력 셀을 확인하고 복제한다. 서민서 XLSX처럼 실제 템플릿이 있으면 이 경로를 우선한다. 원본 형식·수식·병합·시트명을 보존하고 매핑된 명시적 입력 셀만 비운다. 빈 사본에 실제 값을 넣을 때는 [excel-template](references/excel-template.md)에 따라 `scripts/gg_excel_fill.py`를 사용한다. 복제 때 보존한 예시 연도·가격·비율도 현재 근거에 맞게 별도 쓰기 매핑으로 교체한다. 원본 예시의 수식 오류가 확인되면 `gg_excel_formula_patch.py`로 근거·기대 수식(또는 명시적으로 검토한 숫자 상수)·변경 수식을 기록해 사본만 수정한다. 표가 페이지 밖으로 갈라지면 `gg_excel_print.py`의 명시적 인쇄 지도에 따라 사본만 조정하고 실제 PDF에서 가독성을 확인한다. 입력 후 실제 앱 재계산과 본문 대조가 필요하며, 빈 사본 생성만으로 재무 완료를 표시하지 않는다. 템플릿이 없을 때만 `build_excel_finance_template.py <폴더> --input <계산계약.json> --out <새.xlsx>` 레거시 생성기를 사용한다. 레거시 생성물은 학교 제출 양식 대체나 엄격한 원본 양식 검증으로 표시하지 않는다. 두 경로 모두 학교 원문대로 기말 잔여 장부가를 수익에, 경영주 급여가 비용에 없으면 가계비를 투자 비용에 반영한다. 장부가는 시장 처분가격이 아니며 기존 사업 일부 투자에 전체 매출을 사용할 수 없다. 복합·다년생·공유시설·가공·보조금은 원계획을 유지하고 미지원 계산만 보류한다. `scripts/gg_school_paper.py <폴더> --input <논문입력.json> [--out build/검토전_본문.md]`는 겉표지~감사의 글·Ⅰ–Ⅵ 골격과 기상·재해표를 만들며, 미제공 값은 `[확인 필요]`로 남긴다. `scripts/gg.py paper <폴더> --input <논문입력.json>`도 같은 생성기를 호출하며 기본 출력 경로가 같다. 둘 다 기존 산출물을 덮어쓰지 않는다. 이 출력이 `build_docx.py`의 기본 입력이므로 `build_docx.py <폴더>`를 플래그 없이 이어서 실행하면 `build/검토전_논문.docx`가 나온다.

`scripts/gg_office.py`는 macOS Office 샌드박스 파일 접근을 지원하기 위해 전용 그룹 컨테이너(`~/Library/Group Containers/UBF8T346G9.Office/knuaf-doc/`; Windows는 `%LOCALAPPDATA%\\knuaf-doc\\office-jobs`) 작업영역에서 원본을 불변으로 격리 스테이징하여 변환한다.
- Word: `scripts/gg_office.py word <문서.docx> --out-dir <새폴더>` (인쇄 모양 목차/색인 필드 2회 갱신 및 PDF 동시 출력)
- Excel: `scripts/gg_office.py excel <재무.xlsx> --out-dir <새폴더> [--spec <명세.json> 또는 --template-receipt <입력영수증.json>]` (전 시트 used range 재계산 및 단일 세션 PDF 내보내기)
- 일괄: `scripts/gg_office.py batch <파일1.docx> <파일2.docx> <파일1.xlsx> <파일2.xlsx> --out-dir <새폴더>` (UI 클릭 없는 연속 실행, 앱별 최초 권한/시간초과 시 즉시 중단)
산출물은 새 목적지 폴더에만 무덮어쓰기로 발행되며, 원본은 유지된다. 작업영역의 잡 디렉터리는 자동 삭제되지 않으며 `scripts/gg_office.py jobs`로 목록을 보고 `clean --job <ID>`로 지정한 것만 지운다. 영수증의 경로는 작업영역 기준 상대경로다. Office 변환 및 기계 검사 완료는 최종 교수 승인이 아니며 최종 제출 완료로 자동 승격되지 않는다.

본문 재무 수치의 자동 대조는 정본의 범위·기간·항목·값·단위를 같은 절에 명시한 문장으로 제한한다. 현재 자동 대조는 단위 `천원`인 사실만 지원하며 다른 단위의 사실은 `body_finance_crosscheck`에 미지원 단위로 보류된다(자동 통과가 아님). 예를 들어 실제 정본 값으로 `농장A 1년차 매출액은 1,000 천원이다.`처럼 작성한다(기간·범위 순서는 바꿀 수 있다). 쉼표·줄바꿈으로 나눈 각 절에 범위·기간을 반복한다. 다른 항목의 숫자·단위, 전년 값, 문서 다른 곳의 범위를 빌려 통과시키지 않는다. 암묵적 문맥·별도 반올림 규칙은 추정하지 않고 대조 실패로 남겨 근거를 확인한다. 이 기계 대조가 독립 내용검토를 대신하지 않는다.

## 보조 진입점 (레거시)

아래 네 개는 `gg.py`의 얇은 별칭이다. 새 작업에서는 `gg.py`를 쓰고, 이 파일들은
프로젝트가 아직 없는 파일 하나를 볼 때만 쓴다.

| 스크립트 | 같은 일을 하는 gg.py 명령 | 남겨둔 이유 |
|---|---|---|
| `build_status.py <폴더>` | `gg.py status <폴더>` | 없음. 별칭 |
| `lint_evidence.py <폴더>` | `gg.py check <폴더>` | 없음. 별칭 |
| `merge_sections.py <폴더>` | `gg.py export <폴더> --kind review` | 없음. 별칭 |
| `lint_format.py <경로>` | `gg.py check <폴더>` | **`project.json`이 없는 단일 절 파일 하나만 검사할 수 있다.** 그 경우에만 쓴다 |

`gg.py check`는 정본이 있어야 하고 `gg_document.check`까지 포함해 전체를 본다.
단일 파일 검사 결과를 절 승인이나 제출 판정 근거로 쓰지 않는다.
